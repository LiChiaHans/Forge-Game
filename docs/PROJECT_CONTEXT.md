# 最小專案背景

- HTML／CSS／原生 JavaScript 遊戲，GitHub Pages 靜態發布。以直式版面為主，電腦仍維持直式；改功能時不要順手改尺寸或美術。
- 白天經營冶煉廠，夜晚經營餐廳，晚餐完成才進入隔日。每季三天；冬季維持一格結冰。
- 冶煉：礦石、模具、胚料、武器；五個相連在最後落點升兩階。武器有攻防速、屬性、附魔與每款3／6／9把升1／2／3星。
- 餐廳：食材→工序備料→三份配方料理。食物有保鮮，腐壞成廚餘；工序、調味、冰箱、料理補給與獨立技能樹。
- 餐廳新局技能與點數為零，只推出一階食材；首晚後第一點只能料理大師。料理大師解鎖食材升階合成，二／三級返還原階食材機率25%／50%；新技能採買大師獨立增加高階食材推出機率（沿用冶煉採礦表）。舊存檔新技能預設零級。零級仍能備料、完成一階料理。
- 點餐廳客人可取消訂單並扣一心，同一訂單不能重複取消。手持道具不強迫立即使用，仍可放食材；點手持物或直接拖曳才使用。
- 正式技能只能在訓練所花對應點數升級；遊戲內技能鈕只查看已學內容。
- 城鎮含季節／夜景、溫室、圖鑑、建築師與裝飾、每日寶箱、遠征；每局收藏與首頁跨局收藏分開。
- 首頁入口為「圖鑑館」；武器／料理各記住本次開啟期間的排序選擇，依基礎數值在每個階級框架內排序，維持5×2。傳說與終極各自一組；武器箱的純藍圖收藏不排序。同階料理基礎價錢相同，價錢相同時保留原順序，排序不含星級／附魔／調味。
- 溫室室內背景及三種砧板備料素材在art/garden-workshop.js；盆栽七元素×四階段、廚餘木桶維持原生像素SVG。原始食材圖縮至64px畫布內46px，等級標記不縮；成品料理沿用原50張圖。原15張備料托盤圖保留供舊開啟頁面使用，不再列入目前素材表。
- core/asset-loading.js在開場統一預載素材表的全部9組、258項（25,741,556 bytes）；6個併發、圖片逐張解碼檢查，音樂只預載壓縮資料，仍只解碼當季音樂。頁面使用blob URL，不在遊玩時再從網路抓同一素材。CacheStorage的forge-master-media-v1依內容指紋URL重用，完整載入後只清理本遊戲目錄內過期素材；HTML/JS/存檔不放此快取。快取被拒絕時保留記憶體預載，失敗可重試缺少項目或明確選擇先進入；離開頁面不撤銷blob URL，避免破壞返回快取。開場過場在預載後執行，載入期間背景介面inert。新增素材組時須更新collectGameAssets，測試會核對完整素材表；單檔data URI不重新下載。
- 遠征有20關及無限模式，投入武器會消耗；解鎖藍圖以固定階級原料在棋盤合成。冰箱料理戰前選一份，戰中僅能手動使用這份一次；未用不扣庫存，不可更換或追加。
- 正式遊戲使用有限金錢、限購、愛心。後台有獨立資源與跳日，測試成果不影響正式存檔、首頁紀錄／圖鑑或排行榜。
- 排行榜服務已獨立部署，前端沿用 `src/js/online/leaderboard.js` 的原目的地。本次整理不改服務或資料。
- 正常存檔主要為 `forgeSaves`，餐廳保存於 `state.restaurant`；後台獨立 `forgeBackendProgressV1`。保留舊存檔與備份相容。
- 備料與胚料共用不分岔的連線判定，沿線每相鄰三格重疊計算：ABC／BCD／CDE，四連線產2個、五連線產3個、六連線產4個。三格單組在最後落點，多組在各組中間格；各組須從原材料快照計算，先清空來源一次再寫全部成品，避免互相覆蓋。料理全盤掃描，交叉不當成一條五連線。原始礦石／食材另用同階相連合成，交叉五連可在最後落點升兩階。第一晚不提示冰箱整理。
- 城鎮客人以腳底定位於白天冶煉廠／晚上餐廳門前。背景噴水池有固定尋路禁區；日夜首次進城有季節／天數／早晚文字動畫，同時段回城不重播。
- 首頁及城鎮／餐廳／冶煉廠切換由ui/scene-transitions.js提供全暗中點切換與「進入OO」文字。短暫擋輸入、防重複下一天；低動態或不支援動畫API時立即切換。不要在過場期間另做遊戲步數或時間扣減。
- JS原始片段按 `src/build-order.json` 合成單一腳本，維持原共享變數、包裝函式與初始化順序。不要直接將它們各自掛成script或改成ES modules。
- 修改前先用 `docs/function-index.tsv` 定位；不需閱讀完整生成檔、大型素材資料或歷史副本。建置／檢查方式見README。
